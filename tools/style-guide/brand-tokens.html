tehw0lf brand tokens

The palette was never designed in one sitting — it grew across the website, the favicon and the fwdark userstyle, arriving at the same colours each time. This is that palette, named, paired across both themes, and measured.

Brand

One grey, carried since 2022. It fills the avatar and the favicon and stands as the default of the colour embed. Not Material Grey, not Darcula — it has no source outside this workspace. It is the one value that does not shift between themes: it is the mark, not a UI colour.

—#8e8e8e --tw-brand

Two themes

A theme class on <body> — .dark or .light — selects the set. Every ink token is measured against the surface it actually sits on, named in its row; the ratio in each column is against that column's own ground, never the other one's.

Using these in a new app

Copy the token block, then reference it. Two rules carry most of the weight, and both were learned the hard way on this palette.

/* Controls do not borrow --tw-accent: it is tuned for the page
   ground and only reaches 3.79:1 on the control surface. */
button {
  background: var(--tw-control-bg);
  color: var(--tw-control-text);
}

/* In a publishable library, carry the dark value as a fallback so
   a consumer without tokens renders exactly as it does today. */
buttonStyle = input({
  color: 'var(--tw-accent, #cc7832)'
});

Never in Sass

A Sass colour variable compiles to one fixed value and cannot follow the theme. That is what left the light mode wearing dark ink.

Measure against the surface

Not against the page. A colour that clears AA on the ground can fail on a control sitting on top of it.

Semantic stays separate

Success, warning and danger are their own tokens. They never stand in for the accent, and the accent never stands in for them.
